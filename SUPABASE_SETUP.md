# Первая миграция Supabase для Takku

Миграция [20261123000000_initial_takku_schema.sql](supabase/migrations/20261123000000_initial_takku_schema.sql) создаёт схему и справочник языков `et` и `ru`. Начальный каталог будет пустым. Гостевой тренажёр продолжает читать и записывать `localStorage`.

## Применение через SQL Editor

1. Откройте нужный **тестовый** проект Supabase и выберите **SQL Editor → New query**. Для первой проверки используйте проект без предыдущего черновика схемы. Если таблица `public.vocabulary_progress` уже создана вручную, сначала проверьте её данные и подготовьте отдельную миграцию совместимости.
2. Вставьте SQL-файл целиком и нажмите **Run** один раз. Скрипт выполняется в транзакции. При ошибке проверьте сообщение и исправьте причину перед повторным запуском.
3. В **Table Editor** проверьте, что созданы таблицы каталога, личных слов, прогресса и импорта и что на них включён RLS. Схему `takku_private` оставьте вне списка схем, доступных через Data API.
4. Когда понадобится редактор каталога, создайте или выберите пользователя в **Authentication → Users**. Скопируйте его UUID и через SQL Editor добавьте его в список редакторов. По умолчанию список пуст.

   ```sql
   insert into takku_private.catalog_admins (user_id)
   values ('UUID-пользователя-из-Authentication');
   ```

5. Проверяйте доступ через гостевую и обычную пользовательскую сессии. SQL Editor запускает запросы с повышенными привилегиями, поэтому результаты запросов из него сами по себе не подтверждают изоляцию RLS.

## Что хранится

| Таблицы | Данные |
|---|---|
| `languages`, `vocabulary_entries`, `vocabulary_translations` | Языки, словарные записи с UUID, формы, эмодзи и упорядоченные переводы по языкам. |
| `categories`, `vocabulary_categories` | Темы и связи «многие ко многим». |
| `books`, `lessons`, `sources`, `vocabulary_sources` | Учебники, уроки и ссылки на страницы или другие источники. Одна запись может ссылаться на несколько источников. |
| `personal_words` | Личные слова и переводы, доступные их владельцу. |
| `vocabulary_progress` | Прогресс владельца для общего или личного слова и пары языков, позиция в очереди и метаданные синхронизации. |
| `vocabulary_import_jobs`, `vocabulary_import_items` | Закрытые задания для будущего импорта из фото или JSON и строки для проверки перед публикацией. Фотографии в будущем будут храниться в отдельном закрытом бакете. |
| `takku_private.catalog_admins` | Список редакторов. Обычный пользователь не может выдать себе права. |

Гостям доступны язык и опубликованные записи. Связи с категориями и источниками видны, только если опубликованы обе стороны связи. Для уроков и страниц учитывается публикация родительского учебника. Редакторы видят черновики и задания импорта. Права редактора каталога не дают доступа к личным данным пользователей. Редакторы снимают слова с публикации через `is_published`; прямое удаление языков, слов и переводов и изменение их ключей ограничены доверенной ролью базы. Автор и время создания задания импорта задаются базой.

## Совместимость с гостевым прогрессом

- Стадии сохраняют значения из `Progress`. `0` — новое или сброшенное слово, `1` — оригинал → перевод, `2` — перевод → оригинал, `3` — выучено. Для Takku начальная пара — `et` и `ru`.
- Стабильный идентификатор базы — UUID. При будущем наполнении каталога нужно явно сопоставить встроенным записям их существующие числовые ID через `vocabulary_entries.legacy_id`. Для гостевых личных слов используется `personal_words.legacy_id`, уникальный в пределах владельца. При импорте нужно различать встроенные и личные слова по известному сопоставлению каталога.
- При переносе `StoredProgress.queue` нужно сопоставить числовые ID с UUID, убрать дубликаты и назначить позиции с нуля по сохранённому порядку. Активным словам, пропущенным в очереди, нужно назначить позиции в её конце. Для стадий `0` и `3` позиция равна `NULL`. После снятия слова с публикации пользователь сохраняет доступ к своей существующей строке прогресса и может освободить позицию в очереди. Создать новую строку прогресса для такого слова нельзя. Перестановку существующих позиций можно выполнить одной транзакцией с `SET CONSTRAINTS vocabulary_progress_queue_unique DEFERRED`.
- Миграция не читает браузерные данные. Будущему клиенту предстоит предложить перенос после входа, разделять кэши по аккаунтам и согласовывать конфликтующие изменения. `server_updated_at` и `revision` выставляет база. `client_updated_at` передаёт клиент.

## Что понадобится при подключении приложения

Настройте провайдера входа и точные URL возврата в **Authentication → URL Configuration**. Клиенту Vite передавайте URL проекта и публичный ключ. Секреты OAuth и ключ `service_role` в браузерную сборку не передавайте. Хранилище фотографий, его политики, обработчик импорта и клиентская синхронизация относятся к следующим этапам.

## Проверка чтения опубликованного каталога

1. Проверьте, что `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` доступны при **сборке** нужного окружения Cloudflare Pages, затем пересоберите его. Для локальной проверки задайте эти переменные в окружении процесса `npm run dev`. Используйте только публичный ключ проекта.
2. Откройте вкладку **Словарь** и **Network** в DevTools. Запрос `GET /rest/v1/vocabulary_entries` должен вернуть `200`. Пустой ответ показывает пустой общий словарь. При ошибке доступна кнопка «Повторить загрузку».
3. В тестовой базе опубликуйте слово с `language_code = 'et'` и добавьте перевод с `language_code = 'ru'`. В соседней записи оставьте `is_published = false`. После обновления страницы найдите опубликованное слово по оригиналу или переводу и убедитесь, что черновика нет. Публичная категория появится в фильтрах, если привязана к видимой записи.
4. Добавьте новое опубликованное слово в тренировку и обновите страницу. Очередь и стадия сохраняются в `localStorage` текущего браузера. В блокировке запросов DevTools временно отключите запросы к Supabase и повторите обновление для проверки гостевого режима.

У опубликованных слов используется UUID. Если `legacy_id` заранее сопоставлен с ID одного из 42 встроенных слов, Takku использует существующий числовой ID и его прогресс. Сохраняйте это сопоставление при дальнейших обновлениях каталога. Общий словарь загружается с публичным ключом независимо от входа. Личные слова показаны отдельно. Чтобы проверить появление новой публикации, нажмите «Обновить словарь» в гостевом и авторизованном режимах. При подтверждённом отсутствии слова в каталоге его прогресс сохраняется, а слово пропускается в активной очереди.

## Проверка входа по Email и через Google

1. В Cloudflare Pages используйте публичный ключ Supabase с префиксом `sb_publishable_`. Сборка отклоняет другие ключи, переданные в `VITE_SUPABASE_PUBLISHABLE_KEY`.
2. В Supabase проверьте, что включены Email и Google. В шаблоне Magic Link должна быть ссылка `{{ .ConfirmationURL }}`. Адрес приложения, включая завершающий `/` для корневой страницы, должен присутствовать в списке **Redirect URLs**.
3. В профиле выберите «Создать аккаунт» или «Войти», введите email и нажмите «Продолжить с Email». Откройте письмо в том же браузере и профиле, где отправили запрос. Вход использует PKCE. Окно «Войти» отправляет ссылку для существующего аккаунта, окно «Создать аккаунт» допускает создание аккаунта.
4. Выйдите и нажмите «Продолжить с Google». После подтверждения Takku вернётся к профилю. Проверьте email, перезагрузите страницу и убедитесь, что сессия сохранилась. Затем выйдите и проверьте гостевой режим.
5. Откройте словарь до входа, во время сессии и после выхода. Опубликованные слова должны оставаться доступны. Гостевая очередь и прогресс хранятся в прежнем `localStorage` а перенос в аккаунт требует явного подтверждения.

## Облачный прогресс

1. В SQL Editor тестового Supabase откройте **New query**, вставьте и целиком выполните [20261123010000_cloud_progress_sync.sql](supabase/migrations/20261123010000_cloud_progress_sync.sql). Она применяется поверх первой актуальной миграции. Затем примените тот же файл в нужном проекте до публикации клиента. Дополнительные ключи, настройки Auth и изменения Cloudflare не нужны.
2. На компьютере наберите гостевой прогресс, затем войдите. Подтвердите перенос, объединение или использование облачного прогресса. Дождитесь статуса «Синхронизировано». Гостевой снимок в браузере сохранится.
3. На телефоне войдите в тот же аккаунт. Проверьте направления карточек, порядок очереди, выученные и личные слова. Ответьте на карточку, вернитесь к вкладке Takku на компьютере и сравните результат. Активная вкладка также обновляется примерно раз в 15 секунд.
4. Повторите действие без сети и перезагрузите страницу. После восстановления сети дождитесь синхронизации. При одновременном ответе на одну карточку с разных устройств конфликтующее действие остаётся в очереди до явного решения в профиле. Действия для разных слов пересчитываются поверх актуальной очереди.
5. Выйдите и проверьте восстановление гостевого прогресса. Войдите в другой аккаунт и проверьте его отдельную очередь. При возврате в первый аккаунт ранее выбранный перенос не повторяется.

Новая миграция добавляет атомарные операции чтения и записи поверх `vocabulary_progress` и `personal_words`. Она проверяет владельца по `auth.uid()`, сохраняет подтверждения операций и использует ревизии для обнаружения параллельных изменений. Если у встроенного слова ещё нет опубликованного соответствия `legacy_id`, его прогресс хранится через личную запись этого аккаунта. Текущая синхронизация использует пару `et` / `ru`.

SQL-проверки в `test/cloud-progress-sql.sql` рассчитаны на отдельную локальную базу с Supabase-совместимыми ролями и применёнными миграциями. Они проверяют изоляцию, атомарную перестановку очереди и повторы записи после потери ответа.

## Автоматический импорт слов

### Однократная настройка

1. В Supabase откройте **SQL Editor → New query** и выполните [миграцию для импорта](supabase/migrations/20261123020000_import_vocabulary.sql). Она добавляет закрытую SQL-функцию поверх существующих таблиц.
2. Создайте случайный токен длиной не менее 32 символов через менеджер паролей. В **Edge Functions → Secrets** сохраните его под именем `TAKKU_IMPORT_TOKEN`. URL проекта и серверный ключ Edge Function получает от Supabase.
3. Разверните функцию вручную через GitHub Actions. Workflow становится доступен после слияния PR в ветку `main`.

   1. В Supabase откройте [Access Tokens](https://supabase.com/dashboard/account/tokens), нажмите **Generate new token** и скопируйте токен. Используйте аккаунт с правом развёртывать функции проекта Takku.
   2. В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**. Введите имя `SUPABASE_ACCESS_TOKEN`, вставьте токен и нажмите **Add secret**. Токен из этого шага используется GitHub для развёртывания. `TAKKU_IMPORT_TOKEN` остаётся секретом Edge Function для запросов импорта.
   3. В GitHub откройте **Actions → Deploy import-vocabulary → Run workflow**. Выберите `main` и нажмите зелёную кнопку **Run workflow**.
   4. Откройте запущенную задачу. После зелёной галочки проверьте, что `import-vocabulary` появилась в **Supabase → Edge Functions**.

   Workflow развёртывает только функцию. SQL-миграция из первого шага нужна отдельно перед первым предпросмотром. Шлюз пропускает запросы к этой функции без пользовательского JWT, а сама функция проверяет `x-takku-import-token` на сервере.
4. В настройках среды Codex добавьте URL проекта в переменную `TAKKU_SUPABASE_URL`. Сохраните тот же токен как защищённый секрет `TAKKU_IMPORT_TOKEN` для HTTPS-домена проекта. Если у среды ограничена сеть, разрешите именно этот домен. Используйте настройки секретов, чтобы токен не попадал в чат, GitHub или клиентскую сборку.

### Как работает импорт

Прикрепите JSON и попросите предпросмотр. Codex отправит `POST` на `/functions/v1/import-vocabulary` с заголовком `x-takku-import-token` и телом `{"mode":"preview","words":[...]}`. Предпросмотр возвращает `new_words`, `existing_words`, `conflicting_words`, список конфликтов и подтверждение `confirmation`.

После вашего согласия отправляется `{"mode":"commit","words":[...],"confirmation":"..."}` с тем же массивом слов. Подтверждение действует 15 минут. Если содержимое файла или относящиеся к партии строки базы изменились, повторите предпросмотр. Успешная запись публикует новые эстонские слова с русским переводом. Точное опубликованное совпадение переиспользуется, при необходимости добавляется ссылка на источник. Черновики, неоднозначные совпадения и расхождения перевода пропускаются. После записи нажмите **«Обновить словарь»** в Takku.

В массиве может быть от 1 до 500 записей. Обязательные поля — строки `estonian`, `russian` и `source`. Допустимы `emoji` или `emojis` (до трёх подсказок), строка `page` и исходный статус `draft` или `published`. Исходный статус служит метаданными: новые записи публикуются только при подтверждённом импорте. [Пример страницы 20](test/fixtures/tere_page20_words.json).

Для локальной проверки обработчика запустите `npm test`. SQL-сценарии в [import_vocabulary.sql](supabase/tests/import_vocabulary.sql) запускаются через `psql` в отдельной тестовой базе после миграций.
