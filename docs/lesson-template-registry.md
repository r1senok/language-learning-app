# Реестр шаблонов уроков Takku

Срез реализации — коммит `ea45d92`, урок `tere-a1-01`. [Дизайн](lesson-design-spec.md) · [Схема контента](lesson-content-schema.md) · [Ограничения перед импортом](lesson-template-gaps.md).

## Как читать реестр

[LessonReader](../src/lessons/LessonReader.tsx) выбирает представление из упорядоченного массива этапов. Тип этапа `theory` выводит блоки через `TheoryCard`, тип `practice` выбирает задание из `Exercise`. [lessonTemplates.ts](../src/lessons/lessonTemplates.ts) маршрутизирует задания, [engine.ts](../src/lessons/engine.ts) проверяет и записывает результат. Названия в реестре описывают интерфейс. Реальными экспортами являются указанные компоненты.

## Presentation — знакомство с фразами

- **Компоненты.** [TheoryCard](../src/lessons/TheoryCard.tsx), [AudioPhrase](../src/lessons/AudioPhrase.tsx). Блок `phrases` получает массив `{ et, ru, icon? }`. `icon` в этом рендере не читается.
- **Экран.** Хедер → синяя метка «Начнём!» и заголовок → список речевых пузырей с оригиналом и переводом → «Продолжить». Метка, внешние отступы и числовой хедер зависят от ID `greetings-theory`.
- **Проверка и сохранение.** Ответов нет. Нажатие продолжения записывает ID следующего этапа. Прокрутка и просмотр отдельных фраз не сохраняются. Значок звука отображается, воспроизведение в этом блоке не подключено.

## VocabularyAssessment — знакомство со словом

- **Компоненты.** [NewWordCard](../src/lessons/NewWordCard.tsx) и [WordStudyCard](../src/lessons/WordStudyCard.tsx), общая карточка с отдельной тренировкой. Данные `kind: word_intro`, `word: { catalogId, et, ru, forms?, note? }`. Формы опубликованного словаря имеют приоритет над книжной строкой `forms`.
- **Экран.** Хедер и прогресс → «Вы знаете это слово?» → карточка со словом, формами и областью перевода → «Знаю» / «Учить» либо «Продолжить».
- **Проверка и сохранение.** «Знаю» сразу завершает слово в уроке. «Учить» требует доступный `catalogId`, добавляет слово в словарную очередь и сохраняет `wordDecisions[id] = 'learn'`, после чего открывает перевод. «Продолжить» завершает слово, восстановление возвращает раскрытую карточку. Здесь нет самостоятельной проверки перевода и автоматического подтверждения обратного направления. После последнего слова Reader автоматически переходит на следующий этап.

## MultipleChoice — один вариант

- **Компоненты.** [MultipleChoiceCard](../src/lessons/MultipleChoiceCard.tsx), [AnswerGrid](../src/lessons/AnswerGrid.tsx), [QuestionPrompt](../src/lessons/QuestionPrompt.tsx), [ChoiceActionPanel](../src/lessons/ExerciseActionPanel.tsx), маршрутизация через [BookChoiceCard](../src/lessons/BookChoiceCard.tsx).
- **Данные.** `kind: multiple_choice`, `prompt`, `options: { id, text }[]`, `correct`, опциональные `accepted[]`, `instruction`, языки, режим `presentation: text | speech`, `showCorrectAnswer`. Если задан `accepted`, он целиком определяет валидные ID. Для `book.mode: translate` по умолчанию речевой пузырь. У №9 текстовый вопрос. Сетка переключается в компактный режим при количестве вариантов больше четырёх.
- **Экран.** Хедер и прогресс → инструкция → вопрос текстом или с персонажем → сетка → панель проверки. Варианты берутся из данных и перемешиваются по ключу `attemptSeed:questionId`. В №5 часть вариантов отобрана при построении данных из списка фраз, у №8–9 варианты формируются из списков местоимений.
- **Состояния.** Пусто → выбран вариант → проверено. При ошибке выбранная карточка красная, допустимые варианты зелёные. Текст правильного ответа на панели по умолчанию отображается, №5 отключает его через `showCorrectAnswer: false`. Проверка сравнивает ID. После проверки кнопка «Продолжить» доступна по окончании анимации. Выбор и результат сохраняются отдельно, при перезагрузке остаются на проверенной карточке до продолжения.

## MatchingPairs — сопоставление

- **Текущий вариант №7.** [MatchingCard](../src/lessons/MatchingCard.tsx) принимает `pairs: { id, left, right }[]`, инструкции, подписи колонок, подтверждённые ID и callbacks. Обе колонки перемешиваются независимо по ключу попытки и стороны. Экран состоит из хедера без прогресса, инструкции, двух колонок и «Продолжить».
- **Проверка.** Пользователь начинает с любой стороны. Выбор в той же колонке заменяет или снимает отметку. Сравниваются ID пары. Правильная пара кратко зеленеет на 500 мс, затем блокируется. Ошибка подсвечивается на 700 мс, правильная пара при этом не раскрывается. После всех совпадений сохраняется один балл за задание, затем доступно продолжение.
- **Восстановление.** [matchingProgress.ts](../src/lessons/matchingProgress.ts) паркует найденные ID в `choiceDraft.order`, учитывает старые сохранённые пары. Текущая отметка одной стороны и цветовая вспышка сбрасываются. В Reader этот путь привязан к `exercise-7-matching`.
- **Исторический вариант.** [ExerciseCard](../src/lessons/ExerciseCard.tsx) применяется к другим `matching_pairs`. Выбирается левая строка, затем правая; назначения редактируются до общей проверки. После проверки показывается `explanation` и «Продолжить». Проверка сравнивает массив ID в исходном порядке пар. Сохраняется оценка, черновик назначений и экран обратной связи живут в памяти. В активном первом уроке используется только новый вариант.

## FillInBlank — заполнение пропуска

- **Компоненты.** [FillInBlank](../src/lessons/FillInBlank.tsx), `AnswerGrid`, `ChoiceActionPanel`. Входы — `kind: fill_blank` с `sentence: { before, after }` либо сохранённый `multiple_choice` с `book.mode: gap`. В старых данных делится строка по первому `…` или `...`. При отсутствии маркера пробел и пустое место добавляются в конец.
- **Экран.** Хедер и прогресс → инструкция со ссылкой на шпаргалку при наличии → предложение → сетка → панель. Шпаргалка привязана к вопросам №11–12 через ID.
- **Проверка и состояния.** Выбранный текст подставляется в строку. Сетка перемешивается по тому же ключу, что MultipleChoice. Проверка по ID, у книжного варианта учитывается `accepted`. После ошибки выбранная карточка красная, допустимые ответы выводятся текстом в панели. Пустая нижняя кнопка подписана «Продолжить» и заблокирована, после выбора — «Проверить», после обратной связи — «Продолжить».
- **Восстановление.** Тот же черновик и сохранённая оценка, что у MultipleChoice. Доступен один пропуск и один выбор. Заполнения свободным вводом и нескольких пропусков нет.

## WordOrder — сборка предложения

- **Компоненты и вход.** [WordOrder](../src/lessons/WordOrder.tsx), `QuestionPrompt`, `ChoiceActionPanel`. `kind: word_order`, вопрос, `options` с токенами `{ id, text }`, `order` с ожидаемыми ID. Пунктуация в №16 входит в текст токена.
- **Экран.** Хедер и прогресс → инструкция → персонаж с вопросом → поле сборки → банк слов → панель. Порядок банка стабилен в попытке, алгоритм пробует уйти от прямого и обратного порядка правильной строки при совпадающей длине банка и ответа и длине больше двух, см. [wordBank.ts](../src/lessons/wordBank.ts).
- **Состояния и проверка.** Пусто → часть токенов → нужное число токенов → проверено. Нажатие на собранный токен возвращает его в банк, место использованного токена остаётся занятым заглушкой. Достаточно числа токенов в `order`, даже если в банке есть отвлекающие. Валидация требует уникальных ID выбора и сравнивает текст по позициям. Повторяющиеся слова допустимы с отдельными ID. При ошибке панель показывает ожидаемую строку, собранный ответ остаётся видимым. Несколько допустимых последовательностей не поддерживаются.
- **Восстановление.** `choiceDraft.order` сохраняет ID в выбранной последовательности. Seed и оценка восстанавливают банк и блокировку. После получения результата — «Продолжить».

## TheoryReader — теория и справочные материалы

- **Компоненты.** [TheoryCard](../src/lessons/TheoryCard.tsx) обрабатывает `TheoryPanel`. В том же файле находятся рекурсивный `ContentGroup`, `TheoryTable` и `DialogueGroup`. [LessonReferenceSheet](../src/lessons/LessonReferenceSheet.tsx) использует тот же рендер для справочника.
- **Экран.** Часть 4: заголовок и подзаголовок → голубая группа с абзацем, таблицей на две колонки и примечанием → продолжение. Часть 7: заголовок → голубая группа с абзацами и таблицей примеров → два диалога за пределами группы → продолжение. Часть 9: заголовок → голубая группа с абзацем и прокручиваемой таблицей на три колонки → продолжение.
- **Данные.** Порядок задан массивом `panels`. `heading` имеет `label?, title, subtitle?`; `paragraph` и `note` принимают строку или сегменты текста с `lang?` и `emphasis: form | strong`. Группы задают `tone`, `padding` и `edgeToEdge`. Таблицы имеют `title?, headers?, rows, accent?, estonianColumns?, roomy?, scrollable?`. Примеры рендерятся списком или таблицей при наличии `tableHeaders`. Диалоги группируются массивами реплик `{ before, accent, after, ru, side, audioSrc? }`. Фон, таблица и диалог определяются данными. Голубой футер части 4 остаётся привязкой к ID.
- **Состояния.** Чтение и прокрутка. Шпаргалка открывается отдельным диалогом; оценка и выбранный ответ сохраняются при её открытии. Теория не оценивается. Reader сохраняет переход, но не факт просмотра каждого блока. `audioSrc` у диалогов поддерживается на уровне компонента, Reader обработчик не передаёт.

## LessonResult — итог

- **Компонент.** [LessonResult](../src/lessons/LessonResult.tsx) получает `correct, total, errors, percent, best` из `lessonResult()`. Экран включает отдельный хедер, маскота, ободряющий текст, процент и три показателя. Порог среднего текста — 70%, отдельное состояние при 100%.
- **Прогресс.** Итог считает уникальные активные задания с оценкой, без `word_intro`. `@completed` хранит лучший процент. «Завершить» закрывает Reader, «Пройти ещё раз» очищает состояние попытки и сохраняет лучший результат. Итог — служебный экран `@result`, а не редактируемая часть контента.

## Что общее для практики

На уровне локальной попытки Reader хранит `stepId, attempt, best, pending, choiceDraft, stageDrafts, wordDecisions, attemptSeed`. Выбранный вариант или токены записываются сразу, после проверки сохраняется оценка 0/1. При переходе между этапами черновик паркуется по ID этапа. В Supabase синхронизируются оценки и лучший итог; экран, черновики и seed остаются на устройстве. Неподдерживаемый формат показывает сообщение. Такой формат следует исключать из активной последовательности при импорте, иначе перейти дальше обычным путём нельзя.
