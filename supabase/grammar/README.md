# Грамматические формы Takku

Импорт работает с опубликованными эстонскими записями в существующей схеме. Он обновляет два поля каталога: `part_of_speech` и `grammatical_forms`. SQL проверяет UUID, написание, массив русских переводов и точные значения обоих полей. ID, переводы и пользовательские таблицы остаются прежними. Источники и отметки проверки хранятся в архиве партии JSON.

## 1. Экспортировать список

1. Откройте **Supabase → SQL Editor → New query**.
2. Вставьте [export.sql](export.sql), нажмите **Run** и скачайте результат как CSV. Проверьте, что выгружены все 647 строк, включая записи с одинаковым написанием.
3. Передайте CSV и доступные страницы TERE! с видимыми формами или разрешённую выгрузку EKI. Достаточно начать с материалов на 10–20 записей. CSV содержит каталог и его UUID. Пароли, токены и пользовательские данные для работы не нужны.

## 2. Подготовить партию

[batch.json](batch.json) — пустой шаблон массива. Один объект соответствует одному UUID. Поля записи:

| Поле | Значение |
| --- | --- |
| `id`, `lemma`, `russian_glosses` | UUID, точное написание и массив переводов из одной строки экспорта. Порядок переводов сохраняется. |
| `before` | Объект с `part_of_speech` и `grammatical_forms` из экспорта. Исходные пустые значения имеют вид `null` и `{}`. |
| `after` | Объект с теми же ключами и результатом проверки. Все существующие значения сохраняются. |
| `status` | `verified`, `needs_review`, `unverified` или `source_conflict`. В партию для записи включают только `verified`. |
| `sources` | Массив объектов с `kind` и `reference`. Допустимые виды — `tere`, `sonaveeb`, `keeleoppija_sonaveeb`, `ekilex`. Укажите страницу и строку книги, ссылку на конкретную статью/значение или ID записи и версию выгрузки. При нескольких источниках укажите, какие формы подтверждает каждый, например в поле `fields`. |
| `reviewed_by`, `reviewed_on`, `notes` | Кто сверил запись, дата проверки в формате YYYY-MM-DD и комментарий. Для спорных случаев запишите разные значения или формы и причину сомнения. |

Сверяйте эстонскую лемму, русские значения и словарную статью вместе. Например, запись `või` со значением «или» и запись со значением «масло» проверяются отдельно. Если один UUID включает значения из разных частей речи, оставьте его на ручную проверку. Устойчивые выражения сверяйте как отдельные словарные единицы. Не переносите на выражение парадигму одного из его компонентов. Сокращённые формы раскрывайте только по условным обозначениям учебника и сверяйте полную запись с EKI Sõnaveeb или другим надёжным словарём. Если источники конфликтуют, сохраните обе ссылки, отметьте `source_conflict` и отложите строку. Проверьте условия использования источника перед массовой обработкой.

Формы храните строками в объекте `grammatical_forms`. Добавляйте только явно подтверждённые значения:

- `noun` и `adjective` — `nimetav`, `omastav`, `osastav`. Сверяйте, что речь об одной и той же парадигме и о единственном числе.
- `verb` — `ma_infinitive`, `da_infinitive`, `present_1sg` (настоящее, 1-е лицо, единственное число) и `imperative_2sg` (повелительное, 2-е лицо, единственное число). Для `andma` пример структуры — `andma`, `anda`, `annan`, `anna` соответственно. Это контрольный пример из задания. Если в TERE! отсутствует повелительная форма, проверьте её в словаре. Сохраняйте ссылку на подтверждение конкретной формы.
- Другие категории — `pronoun`, `numeral`, `adverb`, `conjunction`, `adposition`, `particle`, `interjection`, `phrase`, `determiner`. Для них партия записывает подтверждённую часть речи или тип записи. Подтверждённые особенности, например склонение местоимения, пока сохраняются со ссылкой в `notes`. Карточка показывает только формы с поддерживаемыми ключами. Пустые и спорные формы опускаются.

Сначала соберите 10–20 проверенных записей и отдельно сохраните спорные строки. Для отчёта отслеживайте четыре числа: записи с подтверждённой частью речи, с хотя бы одной формой, с полным набором применимых форм и на ручной проверке. Считайте по UUID. Партия считается полной, если подтверждены часть речи и все применимые формы. Если в карточке для этой части речи формы не предусмотрены, зафиксируйте это в отчёте отдельно. Неподтверждённое сокращение или пропущенный императив отмечайте как неполную проверку.

## 3. Предпросмотр, запись и откат

1. Сохраните копию экспорта и проверенной партии. Вставьте [import.sql](import.sql) в новый запрос. Внутри блока `$grammar$` замените `[]` проверенным JSON. Если исходный текст содержит сам разделитель `$grammar$`, перед вставкой замените оба разделителя в SQL на одинаковую уникальную метку.
2. Запустите с режимом `preview`. Сверьте `detail`, ожидаемое число `ready` и убедитесь, что `blocked = 0` и `written = 0`. Пустой JSON даёт нулевой отчёт.
3. После ручного подтверждения замените `preview` на `commit` и запустите тот же пакет. При любой конфликтующей или непроверенной строке запись всей партии блокируется. Если PostgreSQL сообщил об ошибке сериализации, выполните свежий предпросмотр и проверьте результат перед повтором.
4. После успешной транзакции сразу сохраните отдельно JSON из `rollback_batch`. Он содержит только строки, изменённые этим запуском. Повторный `commit` показывает `already_applied` и не отменяет необходимость хранить первоначальный пакет отката. Для контроля выполните экспорт снова и сравните результаты по UUID.
5. Для отката вставьте сохранённый `rollback_batch` и запустите `rollback_preview`. Если расхождений нет, переключитесь на `rollback`. Откат проверяет значения и версию строки, записанную исходным импортом. Если после импорта строку отдельно редактировали или изменился русский перевод, SQL блокирует всю партию для ручной проверки.

Этот процесс не требует миграции. Оба режима предпросмотра дают ноль обновлённых строк. При каждом запуске SQL заново сверяет данные в одной транзакции. Грамматические источники и статус проверки храните вместе с исходным экспортом и отчётом импорта вне пользовательских таблиц.


## Текущее покрытие

По сообщённому состоянию базы в каталоге 647 записей. В партии 0 проверенных и 0 частично проверенных UUID. Все 647 записей ожидают сверки. Это сводка по заявленному объёму, а построчный отчёт можно составить после получения экспорта с UUID. Два доступных JSON с TERE! содержат написания и переводы. Для привязки форм нужны CSV из `export.sql` и читаемые фотографии словарных страниц с условными обозначениями либо разрешённая выгрузка словаря.
